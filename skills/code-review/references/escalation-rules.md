# Escalation Rules — Human Intervention

Define when human intervention is required and how to notify the relevant people.

## Escalation conditions

### Hard rules (automatic; no LLM judgment required)

| Rule ID | Condition | Severity | Explanation |
|---------|------|----------|------|
| HR-001 | Changed lines > 500 | WARNING | Oversized PRs are difficult to review automatically |
| HR-002 | Title/description contains "BREAKING CHANGE" | WARNING | Breaking changes need human assessment |
| HR-003 | Title contains "[RFC]" or "RFC:" | INFO | Design discussions require human participation |
| HR-004 | Changes involve 3+ security-critical files | WARNING | Security changes require human confirmation |
| HR-005 | PR is a draft | INFO | Draft PRs are incomplete |
| HR-006 | PR already has CHANGES_REQUESTED | INFO | A human review is already in progress |

### LLM-based escalation (low confidence)

| Condition | Handling |
|------|----------|
| Classification confidence < 0.6 | Downgrade to human_required |
| Review confidence < 0.6 | Downgrade the decision to COMMENT |
| Refactoring core business logic | Mark "Human confirmation recommended" |

## Notification templates

### PR comment: automatic review skipped

```markdown
## 🤖 Automatic Code Review Skipped

Thanks for submitting the PR! It requires human review for the following reason:

**Reason**: {skip_reason}

### Next step
Notify the team in Slack #code-review to request a human review.

---
*Generated by the automatic review system*
```

### CRITICAL security vulnerability notification

```markdown
## 🚨 Critical Security Vulnerabilities Found

The automatic review system found **{n} critical security vulnerabilities** in this PR.

### Vulnerabilities
{issues_list}

### Requirements
1. **Do not merge this PR until the security issues are fixed**
2. Automatic fix PR created: #{fix_pr_number} (requires human review before use)
3. Notify the security team

---
*Generated by the automatic review system*
```

## Security-critical files

Files matching these patterns are considered security-critical:

```
# Authentication
*/auth/*
*authentication*
*authorization*
*login*
*logout*
*session*
*jwt*
*oauth*

# Permissions
*/security/*
*permission*
*access_control*
*acl*
*rbac*
*policy*

# Secrets (excluding test files)
*secret* (exclude test_*.py, *_test.py)
*credential* (exclude test_*.py, *_test.py)
*password* (exclude test_*.py, *_test.py)
*token* (exclude test_*.py, *_test.py)
*key* (exclude test_*.py, *_test.py)

# Payments
*/payment/*
*billing*
*checkout*
*stripe*
*paypal*
```

## Escalation workflow

```
Identify a need for human intervention
  ↓
1. Add an explanatory PR comment using the templates above
2. Set the PR label to "needs-human-review"
3. If a CRITICAL security vulnerability exists:
   - Create a Security Issue marked confidential
   - Notify the security team
  ↓
End the automated workflow and wait for human handling
```
