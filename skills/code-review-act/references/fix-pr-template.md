# Fix PR Template — Automatic Fix PR Format

## PR title format

```
[Auto Fix] PR #{original_pr_number}: {issues_summary}
```

**Examples**:
- `[Auto Fix] PR #42: Fix SQL injection in user_views.py`
- `[Auto Fix] PR #123: Remove hardcoded API keys (2 files)`
- `[Auto Fix] PR #88: Fix SQL injection + XSS vulnerability`

**Summary rules for multiple issues**:
- 1 issue: describe it directly
- 2 issues: `{issue1} + {issue2}`
- 3+ issues: `{n} security/bug fixes`

## PR body template

```markdown
## 🤖 Automatic Fix PR

This PR was generated by the code-review system to fix issues found in PR #{original_pr_number}.

### Issues fixed

{issues_table}

### Changed files

{changed_files_list}

### Validation

1. Check that the fixes behave as intended
2. Run the relevant tests: `{test_command}`
3. Merge this PR after confirming the results

### Notes

- ⚠️ This PR was generated automatically. A human must confirm the fixes before merging
- This PR branches from the head of PR #{original_pr_number}
- Merge it into the branch for PR #{original_pr_number}, rather than directly into main

---
*Generated by the Claude Code Review Skill*
```

## Issues table format

```markdown
| File | Line | Issue type | Severity | Fix |
|------|------|----------|----------|----------|
| app/views.py | 42 | SQL injection | 🔴 Critical | Replace string concatenation with a parameterized query |
| config/settings.py | 15 | Hardcoded secret | 🔴 Critical | Read from an environment variable |
| utils/helper.py | 88 | Missing null check | 🟠 High | Add a None check |
```

## Changed-files list format

```markdown
- `app/views.py` — Fix SQL injection (line 42)
- `config/settings.py` — Remove a hardcoded API key
- `utils/helper.py` — Add a null check
```

## Branch naming

```
auto-fix/pr-{original_pr_number}-{timestamp}
```

**Example**: `auto-fix/pr-42-20260323`

**Rules**:
- Use the `auto-fix/` prefix for identification
- Include the original PR number
- Include the date to avoid duplicates

## Commit message format

Use a separate commit for each file's fix:

```
fix({category}): {description}

Auto-fix for PR #{original_pr_number}
Issue: {issue_description}
File: {filename}:{line}
```

**Example**:
```
fix(security): use parameterized queries to prevent SQL injection

Auto-fix for PR #42
Issue: SQL injection vulnerability in user search
File: app/views.py:42
```

## Scope of automatic fixes

### Automatically fixable issues

| Issue type | Fix method | Risk |
|----------|----------|----------|
| SQL injection | Replace with a parameterized query | Low |
| Hardcoded secret | Replace with os.environ.get() | Low |
| Simple missing null check | Add an if None check | Low |
| Code formatting | Formatting tool | Very low |

### Issues requiring manual fixes

| Issue type | Reason |
|----------|------|
| Business-logic error | Requires domain understanding |
| Architectural issue | Involves multi-file refactoring |
| Complex permission logic | More than one possible fix |
| Performance optimization | Requires knowledge of data scale |

## Labels

Add the following labels to fix PRs if the repository has them configured:
- `auto-fix`
- `security` for security fixes
- `needs-review` for every fix PR, to request human confirmation
